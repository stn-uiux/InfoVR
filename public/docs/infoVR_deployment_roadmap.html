🚀 백엔드 연동 및 프로덕션 배포 로드맵

현재 InfoVR은 프론트엔드 중심(Zustand + IndexedDB)으로 완성된 상태입니다.
이 문서는 실제 운영(Production) 환경 배포 전까지 백엔드를 어떻게 구축하고 연동해야 하는지에 대한 단계별 가이드입니다.
현재 데이터 흐름의 한계 사용자의 모든 3D 공간 배치, 장비 모델, 포트 연결 데이터가 브라우저 로컬 스토리지(IndexedDB)에 저장되어 있습니다.
다른 사용자와 공유하거나 다른 PC에서 접속하려면 반드시 백엔드 중앙 데이터베이스 연동이 필요합니다.
Phase 1

백엔드 아키텍처 설계 및 기술 스택 선정

  • 언어 및 프레임워크 선정: Node.js(NestJS, Express), Python(FastAPI), Java(Spring Boot) 등 팀의 주력 스택 결정.
  • 데이터베이스 선정: 계층형 트리 데이터(전산실 구조)와 JSON 구조(3D 위치 데이터, 장비 커스텀 메타데이터)를 다루기 좋은 PostgreSQL(추천) 또는 MongoDB 선정.
  • 인증(Auth) 시스템 설계: JWT(JSON Web Token) 기반의 로그인 및 사용자/권한 관리(관리자 vs 조회용 뷰어) 체계 설계.
Phase 2

API 명세 설계 및 데이터베이스 스키마 모델링

  • RESTful API 또는 GraphQL 설계: Swagger를 이용해 장비 모델 CRUD, 랙 배치 좌표 저장, 포트 맵핑 저장 API 명세서 작성.
  • 데이터 모델링(스키마): 프론트엔드의 types.ts (HierarchyNode, Rack, RegisteredDevice 등)를 백엔드 ORM Entity(Prisma, TypeORM 등)로 매핑.
  • 이미지 스토리지: 사용자 업로드 커스텀 3D 모델(GLB)과 썸네일(WebP) 이미지를 저장할 AWS S3 버킷 또는 MinIO 스토리지 구성.
Phase 3

프론트엔드 데이터 통신(API 연동) 마이그레이션

  • API 클라이언트 세팅: Axios 또는 React Query(TanStack Query)를 도입하여 서버 데이터 패칭 및 캐싱 층 구축.
  • Zustand 스토어 개편: 기존 IndexedDB에 직접 읽고 쓰던 로직을 API 호출 결과로 상태를 업데이트하도록 변경 (비동기 통신 로직 추가).
  • 초기 데이터 로딩 최적화: InitialLoader.tsx에서 백엔드의 대용량 서버룸 및 장비 데이터를 청크(Chunk) 단위로 불러와 R3F 씬에 렌더링하도록 수정.
Phase 4

인증/인가 및 보안 (Security & Auth)

  • 로그인 페이지 구현: 시스템 진입 전 인증을 위한 로그인 화면 추가.
  • 권한 분리 (Role-based Access): 일반 뷰어(View Mode)는 3D 뷰 및 조회만 가능하고, 관리자(Admin)만 에디트 모드(Edit Mode)를 활성화할 수 있도록 프론트엔드 라우트 가드(Route Guard) 적용.
  • API 보안: 모든 API 요청에 Bearer Token 추가 및 백엔드 인가 로직 점검.
Phase 5

테스트 및 프로덕션 환경 구축 (CI/CD)

  • 클라우드 인프라 세팅: AWS (EC2/EKS) 또는 Vercel (Front) + Render/Heroku (Back) 형태의 인프라 구성.
  • CI/CD 파이프라인: GitHub Actions 등을 통해 main 브랜치 푸시 시 자동 빌드 및 배포되도록 구성.
  • 부하 테스트 (Load Testing): 서버룸 1개당 수백 대의 장비(JSON 데이터)를 클라이언트로 내려줄 때의 트래픽 및 API 응답 속도 최적화 점검.
